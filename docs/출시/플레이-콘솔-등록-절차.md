## 0. 시작하기 전에 — 지금 없는 것 둘

이 둘이 없으면 중간에 막힙니다. 먼저 만들어 두시는 편이 낫습니다.

### ① 심사용 구글 계정 (필수)

하루차림은 **로그인을 해야 쓸 수 있는 앱**입니다. 그러면 플레이는 `앱 액세스 권한` 칸에
**심사자가 실제로 로그인해 볼 계정**을 내라고 요구합니다. 안 내면 "앱을 열 수 없다"로 반려됩니다.
애플도 같은 것을 요구하므로(5.1.1), 하나 만들어 양쪽에 함께 쓰시면 됩니다.

- 새 구글 계정을 하나 만드십시오 (예: `harucharim.review@gmail.com`)
- **2단계 인증을 켜지 마십시오.** 심사자가 문자를 못 받습니다
- 그 계정으로 한 번 앱에 들어가 설정을 마쳐 두십시오 — 심사자가 첫 화면 여섯 개를 답하다 지치지 않게

> 비밀번호는 저에게 알려 주지 마십시오. 콘솔에 직접 넣으시면 됩니다.

### ② AAB 파일 (PWABuilder)

`pwabuilder.com` 에 `https://harucharim.com` 을 넣고 **Package For Stores → Android** 로 받습니다.
**Package ID 는 반드시 `com.harucharim.app`** 이어야 합니다 — `assetlinks.json` 에 그렇게 적어 두었습니다.
받은 zip 안의 `.aab` 파일 하나만 쓰시면 됩니다.

## 4. 올리고 내보내기

### 4-1. 내부 테스트부터
**테스트 및 released → 테스트 → 내부 테스트 → 새 버전 만들기**

1. `.aab` 를 끌어다 놓습니다
2. **Play 앱 서명**을 쓰겠다고 하면 예 (기본값)
3. 출시명·출시 노트를 적고 저장 → 검토 → 출시

### 4-2. ★ 여기서 저에게 주실 것 — SHA-256 지문

AAB 를 한 번 올리고 나면 지문이 생깁니다.

**테스트 및 released → 앱 무결성 → 앱 서명** → **앱 서명 키 인증서** 의
`SHA-256 인증서 지문` (`AB:CD:12:...` 꼴로 32덩이)

이 값을 저에게 주시면 `public/.well-known/assetlinks.json` 을 채워 배포하겠습니다.
**이게 맞아야 주소창 없는 진짜 앱으로 열립니다.** 안 맞으면 위에 크롬 주소창이 남습니다.
채운 뒤 내부 테스트 링크로 설치해 주소창이 사라졌는지 꼭 확인하십시오.

### 4-3. 프로덕션
내부 테스트에서 실제로 잘 열리는 것을 확인한 뒤에 프로덕션으로 올리십시오.

> **확인하실 것** — 2023년 11월 13일 **이후**에 만든 **개인** 개발자 계정은
> 프로덕션 출시 전에 **비공개 테스트를 테스터 12명 이상으로 14일 연속** 돌려야 합니다.
> 그 전에 만드신 계정이거나 단체 계정이면 해당되지 않습니다.
> 콘솔의 프로덕션 화면에 이 조건이 뜨는지 먼저 보십시오. 뜬다면 일정이 2주 늘어납니다.
