## 2. 가입 확인 메일 연결 (15분)

**왜 지금 꼭 해야 하나:** Supabase 기본 발송기는 Supabase 팀원 주소(선생님 관리 계정)로만 편지를 보냅니다.
이걸 안 하면 3번의 심사용 계정도 확인 편지를 못 받고, 공개 뒤 환자분들의 이메일 가입도 전부 막힙니다.
(카카오·구글 로그인은 상관없이 됩니다.)

### 2-1. Resend 에서 도메인이 '확인됨' 인지
1. `https://resend.com` 로그인 → 왼쪽 **Domains**
2. `harucharim.com` 옆이 초록 **Verified** 인지 봅니다
   - **Verified** → 2-2 로
   - **Pending / Failed** → 도메인을 눌러 **Verify DNS Records** 를 한 번 더 누르고 몇 분 기다림
   - **목록에 아예 없음** → [SMTP-연결-절차.md](SMTP-연결-절차.md) 1-2 부터 (DNS 는 이미 있어 바로 Verified 가 날 것입니다)
3. 같은 도메인 화면 **Configuration** 에서 **Click Tracking · Open Tracking 이 꺼져 있는지**(기본은 꺼짐)

### 2-2. API 키 만들기 🔒
1. Resend 왼쪽 **API Keys → Create API Key**
2. Name `supabase-oncofood` · Permission **Sending access** · Domain `harucharim.com` → **Add**
3. `re_` 로 시작하는 키가 **한 번만** 보입니다. **복사 단추**를 누르고 창을 닫지 마십시오

### 2-3. Supabase 에 붙이기
1. Supabase `oncofood` → **Authentication → Emails** → 위쪽 탭 **SMTP Settings**
2. **Enable Custom SMTP** 를 켭니다
3. 칸을 채웁니다

| 칸 | 값 |
|---|---|
| Sender email | `no-reply@harucharim.com` |
| Sender name | `하루차림` |
| Host | `smtp.resend.com` |
| Port number | `465` |
| Minimum interval | 그대로(60초) |
| Username | `resend` |
| Password | 🔒 2-2 에서 복사한 `re_…` 키 붙여 넣기 |

4. **Save changes**

### 2-4. 보내는 양 한도
**Authentication → Rate Limits** → `Rate limit for sending emails` 가 **30** (시간당) 인지. 아니면 30 으로 저장.
(Resend 무료는 하루 100통입니다. 넘지 않게 막는 난간입니다.)

### 2-5. 한국어 편지 넣기
**Authentication → Emails → Templates** 탭

| 서식 | Subject 칸 | Body 칸 |
|---|---|---|
| **Confirm signup** | `[하루차림] 가입을 마무리해 주세요` | 이 맥의 `harucharim-app/supabase/email-templates/confirm-signup.html` 내용 통째로 |
| **Reset Password** | `[하루차림] 비밀번호를 다시 정하는 주소입니다` | `reset-password.html` 내용 통째로 |

- 파일 여는 법: Finder → **⌘ + Shift + G** → `~/클로드 작업/harucharim-app/supabase/email-templates` → 파일을 **텍스트 편집기**로 열고 ⌘A · ⌘C
- 각각 **Save**

**끝나면:** 바로 3번으로 (3번이 이 단계의 시험입니다).

## 3. 심사용 계정 만들기 · 계정 삭제 시험 (10분)

### 3-1. 심사용 계정
1. **시크릿 창**(크롬 ⌘ + Shift + N)에서 `https://harucharim.com`
2. "만 14세 이상입니다" 체크 → **이메일로 하기 → 처음이에요 (가입)**
3. 이메일 `rohkwangwon+review@gmail.com` · 비밀번호 🔒 새로 정함(8자 이상, 평소 쓰시는 것과 다르게, 따로 적어 두기)
4. Gmail 받은편지함에서 확인합니다

| 볼 것 | 맞으면 | 다르면 |
|---|---|---|
| 편지가 왔는가 | 1~2분 안에 | Resend → **Emails** 에 기록이 있나 → 없으면 2-3 값 다시 |

| 제목·본문 | 한국어, 초록 단추 | 2-5 |

5. 초록 단추를 누르면 `harucharim.com` 으로 돌아오는지 (엉뚱한 곳이면 1번 Site URL)
6. 들어간 뒤 아래쪽에 **'문의 관리' 단추가 없는지** — 있으면 관리자 주소로 만든 것이니 지우고 다시

### 3-2. 계정 삭제 시험 — 다른 주소로
심사용 계정은 남겨야 하므로 **시험용을 하나 더** 만듭니다.

2. **내 정보 → 계정 삭제** → 끝까지 진행
3. 같은 주소로 다시 로그인을 시도 → **로그인이 안 되거나 새 가입으로 시작되면** 정상

**끝나면 저에게:** "메일 연결·심사용 계정 끝" (비밀번호는 빼고)

## 7. 내부 테스트에 AAB 올리기 → 앱 서명 지문 (20분)

### 7-1. 올리기
1. 왼쪽 **테스트 및 출시 → 테스트 → 내부 테스트** → **테스터** 탭 → **이메일 목록 만들기** → 이름 `나` · 선생님 구글 주소 → 저장
2. **버전** 탭 → **새 버전 만들기**
3. **Play 앱 서명** 안내가 나오면 기본값 그대로(**Google 에서 관리**) 계속
4. **App Bundle** 칸에 이 파일을 끌어다 놓습니다
   `~/클로드 작업/harucharim-app/android-twa/app-release-bundle.aab`
   (Finder → ⌘ + Shift + G → `~/클로드 작업/harucharim-app/android-twa`)
5. 출시명은 자동(`1 (1.0.0)`) · 출시 노트 `첫 버전` → **다음 → 저장 → 출시**

### 7-2. ★ 앱 서명 지문 — 이것만 저에게 주십시오
1. 왼쪽 **테스트 및 출시 → 설정 → 앱 무결성** → **앱 서명** 탭
2. **앱 서명 키 인증서** 상자의 **SHA-256 인증서 지문** — `AB:CD:12:…` 처럼 콜론으로 이은 32덩이
3. 옆의 복사 단추로 복사해 **저에게 붙여 넣어 주십시오.** (이것은 공개해도 되는 값입니다. 비밀이 아닙니다)
   → 제가 `assetlinks.json` 에 두 번째 지문으로 더해 배포합니다. 이게 있어야 스토어에서 받은 앱이 **주소창 없이** 열립니다.
   - 같은 화면의 **업로드 키 인증서** 지문은 `8B:D1:53:…:9E:31` 이어야 합니다(이미 넣어 둔 것). 다르면 알려 주십시오.

### 7-3. 설치 확인 (안드로이드 폰이 있으면)
1. 내부 테스트 → **테스터** 탭 아래 **링크 복사** → 안드로이드 폰에서 열기 → **테스터 되기** → 플레이 스토어에서 설치
2. 제가 지문을 배포했다고 알려 드린 뒤 앱을 열어 **위에 주소창이 없으면** 성공
3. 폰이 없으시면 건너뛰셔도 됩니다 — 콘솔 **성장 → 딥 링크** 화면에서 `harucharim.com` 이 '확인됨'인지로 대신 봅니다

1. **테스트 및 출시 → 테스트 → 비공개 테스트** → **트랙 만들기**(이름 `테스트`) 또는 기본 **Alpha**
2. **국가/지역** 탭 → 대한민국 추가
3. **테스터** 탭 → 이메일 목록 만들기 → **안드로이드 폰을 쓰는 12명 이상**의 구글 계정 주소(넉넉히 15명 권함 — 중간에 빠지는 분 대비)
   - 아이폰 사용자는 안 됩니다. 가족·병원 동료·직원 중 안드로이드 쓰시는 분
4. **버전** 탭 → 새 버전 → **라이브러리에서 추가**로 7번의 같은 AAB 선택 → 출시 → 검토(하루 안팎)
5. 승인되면 **링크 복사** → 테스터분들께 카카오톡 등으로 전달: "링크 열기 → 테스터 되기 → 설치 → **14일 동안 지우지 말고** 가끔 열어 보기"
6. 콘솔 대시보드에 "테스터 ○명, ○일째" 가 나옵니다. **12명 이상이 연속 14일** 이 차면 프로덕션 신청 단추가 열립니다
7. 신청할 때 테스트 소감 설문(테스터 모집 방법·받은 의견·출시 준비 이유)을 씁니다 — 그때 저에게 화면 문항을 붙여 주시면 답안을 써 드립니다

## 9. 프로덕션 출시 신청

1. **테스트 및 출시 → 프로덕션** → **국가/지역** 대한민국 → **새 버전 만들기** → 라이브러리에서 같은 AAB → 출시 노트 → **검토 시작**
2. 심사는 보통 며칠, 길면 1주 넘게 걸립니다. 반려 메일이 오면 그대로 붙여 주십시오
3. 심사 기간에는 서버(Supabase)가 멈추지 않는지 매일 점검이 돌고 있습니다 — 멈추면 '작업 실패' 메일이 옵니다

## 10. 기한 두 가지 (각 2분, 아무 때나)

## 회신이 정한 선 — 앞으로 기능을 더할 때

식약처가 '해당 없음' 으로 본 것은 **"입력한 상황에 맞는 식생활 정보를 근거 문헌과 함께 제공하는 식생활·영양관리 소프트웨어"** 입니다.
진단·예후 관찰, 치료 반응 예측, 치료 효과·부작용 모니터링으로 읽힐 기능(예: 부작용 등급 판정, "재발 위험 ○ % 감소")과
웨어러블 연동은 더하기 전에 다시 물어야 합니다. 스토어·게시물에 "재발을 막는", "면역력", "치료 효과" 는 쓰지 않습니다.
