## 2. 전체 설명 (플레이 4,000자 / 앱스토어 동일 사용 가능)

```
암 진료실에서 가장 자주 나오는 질문이 "뭘 먹어야 하나요"입니다.
그런데 그 답을 정리해 드릴 시간은 가장 적습니다.
하루차림은 그 자리를 근거로 채우려고 만든 앱입니다.

■ 지금 이 사람에게 맞는지 판정합니다
암종, 치료 시기, 동반 증상, 드시는 약을 받아
눈앞의 음식 하나에 대해 권장·주의·피하세요 가운데 하나를 알려 드립니다.
같은 회라도 호중구가 낮은 시기와 회복기의 답이 다릅니다.

■ 모든 문장에 출처가 붙습니다
참고 문헌 79종을 모두 원문으로 대조했습니다.
각 항목을 누르시면 어느 문헌에서 나온 말인지, 근거가 얼마나 단단한지 보실 수 있습니다.

■ 근거를 부풀리지 않습니다
"아직 모릅니다"라고 적힌 항목이 여럿 있습니다.
확실한 것과 불확실한 것을 섞어 놓으면 확실한 것까지 믿지 않게 되기 때문입니다.

■ 한국 밥상 위에서 판단합니다
식품 18,000여 종. 국·찌개·김치·젓갈처럼 실제로 문제가 되는 자리를 1회 제공량 기준으로 봅니다.
추천도 밥 + 반찬 두셋 + 국이라는 한 상의 꼴을 지킵니다.

■ 약과 음식의 상호작용
와파린과 비타민 K, 자몽과 표적치료제, 보르테조밉과 녹차처럼
실제로 문제가 되는 조합을 약제 18종에 대해 확인해 드립니다.

■ 무엇을 담고 있나
· 암종 10가지 (유방·위·대장·폐·간·전립선·췌장·식도·두경부·부인암)
· 증상과 상태 17가지 (연하곤란·구강점막염·호중구감소·위절제후·장루·복수 등)
· 임상 규칙 144개, 참고 문헌 79종
· 하루 식단 추천, 식사 기록, 주간·월간 영양 평가, 영양제 안내, 바코드 검색

■ 기록은 기기 안에 남습니다
적어 두신 암종·체중·식단은 이 기기에만 저장되며 서버로 보내지 않습니다.
로그인은 문의하신 내용에 답을 드리기 위한 것입니다.

■ 식품이나 보충제를 팔지 않습니다
추천에 상업적 이해가 개입하지 않습니다.

암 환자를 25년간 치료해 온 방사선종양학과 전문의가 내용을 감수했습니다.

※ 이 앱은 의료기기가 아니며 진단·치료를 목적으로 하지 않습니다.
   담당 의료진의 지시가 언제나 우선합니다.
```

## 3. 스크린샷에 넣을 문구 (6장 기준)

| # | 화면 | 문구(큰 글씨) | 아래 한 줄 |
|---|---|---|---|
| 1 | 내 식단 | 오늘 무엇을 드실지 | 암종·시기·증상에 맞춰 한 상으로 |
| 2 | 이유 펼침 | 왜 이걸 권하는지까지 | 규칙마다 근거 등급과 출처가 붙습니다 |
| 3 | 찾기(판정) | 이거 먹어도 되나요? | 검색 한 번으로 권장·주의·피하세요 |
| 4 | 영양제 | 이건 근거가 있고, 이건 없습니다 | 복용 중인 약과의 상호작용까지 |
| 5 | 기록 | 일주일치를 모아 보면 보입니다 | 모자란 것과 넘치는 것을 짚어 드립니다 |
| 6 | 가이드 | 참고 문헌 79종, 전부 원문 대조 | 근거를 부풀리지 않습니다 |

세로 스크린샷 6장(1290×2796 이상), 각 문구는 상단 25 % 안에 두십시오.

## 5. ✅ 개인정보 라벨 — 그대로 답하시면 됩니다

### 애플 App Privacy

| 질문 | 답 |
|---|---|
| 데이터를 수집합니까? | 예 (아래 두 가지만) |
| 연락처 정보 → 이메일 | **앱 기능에 연결** · 추적 안 함 — 문의 답변용 |
| 식별자 → 사용자 ID | **앱 기능에 연결** · 추적 안 함 — 로그인 식별용 |
| 건강 및 피트니스 | **수집 안 함** ← 기기 안에만 저장하므로 |
| 사용 데이터 | 별도 동의 시에만 · **연결 안 됨** · 추적 안 함 (암종·치료시기를 뭉갠 값) |
| 앱 추적 투명성(ATT) | 사용하지 않음 |

### 구글 플레이 데이터 보안

| 질문 | 답 |
|---|---|
| 데이터 수집 | 이메일, 사용자 ID (필수) · 앱 이용 통계 (선택, 동의 시) |
| 데이터 공유 | 없음 |
| 전송 중 암호화 | 예 |
| 데이터 삭제 요청 | 예 — 앱 내 `내 정보 → 계정 삭제` 및 웹 양식 |
| 건강 데이터 | **수집하지 않음** (기기 내 저장) |

> 이 답이 사실과 맞는지는 `privacy` 검사가 매 빌드마다 확인합니다.
> 앱 문구를 고치실 때 이 표도 함께 보십시오.

## 7. ✅ 남은 관문 세 가지 (코드로 끝나지 않는 것)

| 관문 | 무엇이 필요한가 | 지금 상태 |
|---|---|---|
| **구글 플레이 (TWA)** | `https://도메인/.well-known/assetlinks.json` 이 **주소 뿌리**에 있어야 함 | ⛔ 도메인 없음 — `github.io` 하위 경로에는 놓을 자리가 없음 |
| **애플 4.2** | 웹뷰만 씌운 앱은 반려. 네이티브 기능이 필요 | ⛔ 미착수 — 푸시 알림 또는 바코드 네이티브 연동(Capacitor) |
| **애플 5.1.1(v)** | 로그인 필수 → 심사 메모 + 심사용 계정 | ✅ 위 6번 원고 준비됨 · 계정만 만들면 됨 |

**순서상 도메인이 첫 단추입니다.** 도메인이 없으면 플레이도, 처리방침 URL도, 도메인 메일도 막힙니다.
절차는 `docs/출시/도메인-구입과-연결-절차.md` 를 보십시오.
