- 낼 문서는 다 되어 있습니다(19쪽 PDF).
- 내기 전에 **4항만 직접 읽어 주십시오.** 앱이 실제로 하는 말을 숨김없이 적은 부분입니다.

- 따라 하기: `docs/법무/식약처-질의-제출-방법.md`
- 회신을 기다리는 동안 아래 ②~⑤는 **진행하셔도 됩니다.** 공개 출시(⑦)만 회신 뒤로 미룹니다.

### ② Supabase 주소 설정 확인 (1분)

Supabase → `oncofood` → Authentication → URL Configuration 에서 Site URL 이 `https://harucharim.com` 인지.
가입 확인 편지의 단추가 이 주소로 사람을 돌려보냅니다. 제가 밖에서는 볼 수 없는 값입니다.

### ③ 가입 확인 메일 연결 (SMTP) — **아직 안 됨**

- 지금은 Supabase 기본 발송기라 **시간당 몇 통**만 나갑니다. 시험 삼아 한두 명 가입하는 데는 지장 없지만, 공개하면 가입이 막힙니다.
- 할 일: Resend 가입 → 가비아에 DNS 3~4줄 → Supabase 에 연결 → 한국어 편지 서식 붙여 넣기
- 10월 13일 확인: 가비아에 Resend 용 DNS 가 아직 없습니다.
- 따라 하기: `docs/출시/SMTP-연결-절차.md`

### ④ 심사용 계정 만들기

- 앱에서 이메일로 가입: **`rohkwangwon+review@gmail.com`** (편지는 평소 메일함으로 옵니다)

### ⑤ 구글 플레이에 올릴 파일 만들기 — **아직 안 됨**

- pwabuilder.com → `https://harucharim.com` → Package For Stores → Android
- Package ID 는 반드시 **`com.harucharim.app`**
- 받은 zip 의 `signing.keystore` 와 `signing-key-info.txt` 는 **잃어버리면 업데이트를 못 올립니다.** 안전한 곳에 두시고 누구에게도 보내지 마십시오.
- `.aab` 를 플레이 콘솔 **내부 테스트**에 올린 뒤, 콘솔의 **SHA-256 지문**을 저에게 주시면 `assetlinks.json` 을 채워 배포합니다. (지금은 빈칸입니다)
- 따라 하기: `docs/출시/플레이-콘솔-등록-절차.md`

**권장의 문턱 — 근거 검토 결과**

"단백질이 많아 권장", "칼슘이 많아 권장"을 붙이려면 1회 분량에 얼마가 들어 있어야 하는가의 숫자입니다.

- 처음 숫자(단백질 5 g · 칼슘 80 mg)에는 **출처가 없었습니다.** 제가 어림으로 잡은 것이었습니다.
- 식약처 「식품등의 표시기준」의 '함유 또는 급원' 기준으로 바꿨습니다.
  1회 분량에 1일 영양성분 기준치의 10 %(단백질) · 15 %(무기질) 이상 → **단백질 5.5 g · 칼슘 105 mg**.
  마시는 것은 고시대로 100 mL 당 그 절반(단백질 2.75 g · 칼슘 52.5 mg).
- 출처: 식약처 「한눈에 보는 영양표시 가이드라인」(2024.12) 39쪽, 1일 영양성분 기준치 단백질 55 g · 칼슘 700 mg.
- 이 바꿈으로 '권장'이 빠지는 것(내장 식품 기준): 단백질 5종(병아리콩 60 g, 렌틸콩 60 g, 땅콩 20 g, 멸치볶음 15 g, 콩자반 30 g),
  칼슘 12종(청경채 80 g, 슬라이스치즈 1장, 잔멸치볶음 40 g 등). 피해야 할 음식이 새로 생기는 것은 없습니다.
- **한계:** 이 고시는 식품 포장에 쓸 말을 정하는 기준이지 환자에게 권할 기준이 아닙니다.
  "1회 분량에 이만큼"을 권장의 문턱으로 삼은 것 자체는 이 앱의 판단입니다. 다른 숫자가 낫다고 보시면 한 곳만 고치면 됩니다.

### 근거를 확인하다가 함께 고친 것 — 알고 계셔야 할 것

호중구가 낮다는 것은 앱에서 두 군데서 고를 수 있습니다 — **치료 시기**('호중구감소 시기')와 **증상**('호중구감소증').
두 길의 답이 달랐습니다.

| | 시기로 고르신 분 | 증상으로만 고르신 분 (고치기 전) |
|---|---|---|
| 회덮밥 · 육회비빔밥 | 피하세요 | **표시 없음** |
| 모듬회 | 피하세요 | **권장** |
| 사과 · 상추 | 권장 | **피하세요** |

이제 두 길 모두 왼쪽 칸과 같습니다. 그래서 **증상에서 호중구감소증을 고르신 분께는 생과일·생채소가 더 이상 '피하세요'가 아닙니다**
(씻거나 껍질을 벗겨 드시면 된다는, 앱이 원래 밝혀 둔 입장대로입니다. 새싹채소는 여전히 익혀 드셔야 합니다).
생과일·생채소도 막는 쪽이 맞다고 보시면 말씀해 주십시오 — 그 경우 두 길 모두 그렇게 바꿉니다.

| 생과일·생채소가 나오면 섭취 방법을 반드시 함께 | 호중구가 낮은 분께 사과·상추·샐러드가 나오면 이름 바로 아래에 "흐르는 물에 씻어서 드세요 — 껍질을 벗겨 드실 것도 벗기기 전에 씻습니다"가 붙음(추천·내 식단·찾기·상세 네 화면). 앱에 적혀 있던 "껍질을 벗겨 드시면 됩니다"는 FDA 원문에 없어 고침 |

| 모든 표기는 근거 기반 | 문헌 8종을 새로 받아 인용(87종). 날것 규칙 4건의 등급을 B → G로 바로잡음(메타분석이 아니라 FDA 지침이 출처) |

**대규모 랜덤 입력 시험에서 찾아 고친 것**

- **체중·키·나이 칸이 친 값을 그대로 저장했습니다.** 키에 0을 넣으면 BMI가 "Infinity"로 뜨고, 나이에 1000을 넣으면 1000세로 목표를 셈했습니다. "60"을 치는 도중의 "6"도 저장됐습니다. 이제 범위(체중 20~300 kg, 키 100~230 cm, 나이 1~120세) 안의 값만 저장하고, 벗어나면 칸 아래에 알려 드립니다.
- 체중 기록에도 같은 문을 달았습니다(1000 kg이 한 번 들어가면 감소율이 통째로 틀어집니다).
- 손으로 등록한 라임에만 자몽 경고가 빠져 있었습니다.
- **"목표 범위에 들어옵니다"라고 적었는데 실제로는 범위 밖인 문구가 네 군데 있었습니다.** 1,701 kcal을 두고 "목표 범위(1,416~1,616 kcal)에 들어옵니다", 식이섬유 5 g을 두고 "목표(8~15 g) 안에 있습니다". 15 %까지는 맞춘 것으로 치는 계산이 문구에까지 번진 것입니다. 넘으면 넘었다고, 모자라면 모자라다고 적게 고쳤습니다.
