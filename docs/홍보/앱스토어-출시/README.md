**홍보물은 App Store 만 싣습니다.** 안드로이드는 "출시 예정"이라고만 적고, 웹 주소는 싣지 않습니다(2026-11-25 선생님 결정).

**QR 은 모두 `harucharim.com/get` 하나입니다.** 아이폰으로 비추면 App Store 로 바로 가고, 안드로이드로 비추면 "안드로이드 앱은 출시 예정입니다" 안내가 뜹니다(`public/get/index.html`).
구글 플레이가 열리면 그 페이지의 `ANDROID` 주소만 채우면 되고, 이미 인쇄한 포스터·카드는 그대로 씁니다.

웹(harucharim.com)을 아이폰 사파리로 여는 분께는 화면 맨 위에 **App Store 받기 띠**가 자동으로 뜹니다(애플 '스마트 앱 배너', `index.html`).

다시 만들기: `python3 scripts/promo/build-launch.py && zsh scripts/promo/print-launch.sh` — 숫자는 `docs/보고서/numbers.json` 에서만 읽습니다.
영상 다시 만들기: `python3 scripts/promo/build-launch-video.py <작업폴더>` → 해설은 `scripts/promo/mp4/narration-launch.json`(장면 7개),
시간표는 `scripts/promo/mp4/timeline-launch.py`, 찍기·인코딩은 `scripts/promo/mp4/README.md` 순서 그대로(목소리 Sulafat·Umbriel, 빠르기 0.95, 문장 사이 0.6초).

## 홍보 방법 — 권하는 순서

1. **진료실 안 (가장 먼저, 가장 확실)** — 이 앱이 필요한 분은 이미 대기실에 계십니다.
   대기실에 포스터 한 장, 방사선치료를 시작하시는 날 카드 한 장. "식사는 어떻게 하냐"는 질문이 나올 때 카드를 건네시면 됩니다.
   ※ 병원 게시물 규정이 있으면 먼저 확인하십시오. 포스터에는 병원 이름·의사 이름이 없습니다.
2. **함께 일하는 사람들** — 간호사·영양사·종양내과·외과 동료. 환자에게 가장 자주 식사 질문을 받는 분들입니다. 아래 '동료 의료진용' 문구 + 전문가용 자료(`docs/홍보/하루차림-무엇이-다른가.html`).
3. **환자·가족 모임(카카오톡 단톡방·카페)** — 운영자에게 먼저 여쭙고 올리십시오. 홍보 글은 한 번만, 그다음은 질문이 나왔을 때 답으로.
4. **블로그·인스타그램** — `../게시물-문구.md` 와 `../잘못-알려진-이야기.html` 의 "확인해 보니 이랬습니다" 글이 앱 소개보다 더 멀리 갑니다. 글 끝에 정사각 그림 한 장.
5. **App Store 상품 페이지 자체** — '프로모션 텍스트'(170자, 심사 없이 언제든 바꿀 수 있음)가 비어 있습니다. 아래 문구를 넣으면 앱 이름 바로 아래에 보입니다.
6. **안드로이드 출시 때 한 번 더** — 그때 "안드로이드도 나왔습니다"로 알립니다(지금 자료에는 '출시 예정'만).

### 하지 말 것 (규정·원칙)
- **별점·리뷰를 부탁하지 않습니다.** 애플 지침(5.6.1)은 앱 안의 정해진 방식 말고 따로 리뷰를 조르는 것을 막고, 환자분께 부담이 됩니다.
- 환자용 자료에 **'무료'·'판매 없음'·'전문의가 만든'** 을 쓰지 않습니다(나중에 바뀔 수 있는 약속, 만든 이를 내세우는 말 — `../게시물-문구.md` 0절).
- **효능을 말하지 않습니다** — '재발을 막는', '면역력', '치료 효과'. 식약처 회신의 조건(의료기기법 제26조)과도 맞물립니다.
- 애플 로고나 'App Store 다운로드' 배지 그림을 흉내 내지 않습니다. 'App Store' 글자만 씁니다(정식 배지는 애플 마케팅 도구에서 받아 규정대로).
- 바코드를 말할 때는 **"영양성분까지 바로 나오는 제품은 약 20 %"** 를 함께 적습니다(이 자료들은 바코드를 말하지 않습니다).
- 개인 연락처·병원 이름을 환자 단톡방 글에 넣지 않습니다. 구글 계정 주소 같은 것은 1:1 로만.
