# 수정 갈래 공통 지침 (반드시 끝까지 읽을 것)

먼저 같은 폴더의 BRIEF.md(배경·금지)를 읽으세요. 그다음 배정된 findings-*.json 을 읽으세요 — 원문 대조 갈래가 찾은 오류와 원문 인용이 있습니다.
앱: /Users/kwangwonroh/클로드 작업/harucharim-app (한국어 암 환자 식이 앱, 사용자는 방사선종양학과 전문의).

## 고칠 수 있는 것 (배정된 파일 안에서만)
1. **인용-주장 불일치**: 출처에 없는 문장은 (a) 원문이 공개된 출처(PMC 전문·기관 공개 문서)로 근거를 바꾸거나 (b) 출처가 실제로 말하는 만큼으로 줄인다. 출처 원문 문장을 직접 열어 확인한 것만 쓴다(findings 의 source_quote 를 믿지 말고 다시 열어 볼 것 — 최소한 핵심 숫자는).
2. **숫자**: 원문과 다른 숫자, 하위군 값을 전체처럼 쓴 것, 오즈비를 상대위험처럼 쓴 것 등을 바로잡는다.
3. **범위(scope)**: 근거가 다루지 않는 음식·영양제에 붙는 것을 match 조정(excludeTags, groups 한정, supplementIds 한정, minServing 등 기존 RuleMatch 기능)으로 좁힌다. 소금에 '권장'이 붙는 것처럼 명백히 틀린 것.
4. **등급(evidence)**: 인용한 연구 설계에 맞춘다(A=RCT·메타, B=대규모 전향 코호트, C=소규모·후향·기전·종설, G=주요 학회·기관 지침 합의). 출처를 바꾸면 등급도 다시 본다.

## 하지 말 것
- **판정 수준(level: prefer/caution/avoid/info)을 바꾸지 마라.** 바꿀 근거가 있으면 judgements 에 제안만 적는다. (예외: 범위를 좁혀 엉뚱한 대상에서 떼는 것은 해도 된다 — 그건 수준 변경이 아니다.)
- 규칙을 새로 만들거나 지우지 마라(제안만).
- **src/data/references.ts 를 수정하지 마라.** 새 출처·출처 주석 추가는 결과 JSON 의 new_refs / ref_annotations 에 적으면 코디네이터가 합친다. 새 출처 id 를 규칙 refIds 에 미리 써도 된다(합칠 때 맞춘다) — 단 id 는 new_refs 에 반드시 정의.
- 배정되지 않은 파일을 수정하지 마라. 다른 수정 갈래가 동시에 다른 파일을 고치고 있다.
- 블로그·개인 사이트, NCCN 구독자 PDF, Liverpool API 우회 금지. 초록만 볼 수 있는(구독제) 문헌을 새로 넣지 마라 — "참고 문헌 전부 원문 대조"를 지켜야 한다. 원문 공개 대체를 못 찾으면 문장을 줄인다.
- 전문의가 이미 정한 것(자몽 판정 수준, '금기' 낱말 금지, 덜 익힌 동물성 '피하세요', 석류·아마씨·칡·로열젤리 오늘 문구)은 건드리지 마라.

## 문체
- 환자에게 쓰는 존댓말, 짧고 쉬운 문장. 기존 문장 결을 따를 것. 숫자에는 단위·대상(누구를 몇 명 몇 년)을 붙인다.
- 코드 주석: 왜 바꿨는지 한두 줄(기존 주석 결을 따름, "2026-10-14 전수 대조" 표기).

## 숫자엔 출처 — 자동 검사
scripts/checks/numbers.ts 가 규칙 제목·이유의 숫자(10 이하 정수 제외)가 **그 규칙이 인용한 출처의 citation 문자열**(괄호 주석)에 있는지 본다. 그래서:
- 네가 고친(또는 손대지 않은) 규칙의 숫자마다, 원문에서 확인했으면 ref_annotations 에 "그 출처 citation 괄호에 덧붙일 짧은 한국어 주석(숫자 포함)"을 적어라. 형식 예: "SELECT 35,533명 무작위 · 비타민 E 군 전립선암 HR 1.17(99 % CI 1.004~1.36)".
- 확인 못 한 숫자는 문장에서 빼거나 고쳐라. 위험비에서 계산한 % (HR 0.72 → 28 %)는 검사가 자동 통과시킨다.
