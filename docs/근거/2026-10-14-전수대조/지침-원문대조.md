# 하루차림 근거 전수 대조 — 공통 지침 (반드시 끝까지 읽을 것)

## 배경
하루차림은 암 환자용 식이·영양 앱이다(한국어). 화면의 모든 판정(권장 prefer / 주의 caution / 피하세요 avoid / 참고 info)은
규칙에서 나오고, 규칙마다 사용자에게 보이는 제목(title)·이유(reason)·근거 등급(evidence)·출처(refIds)가 있다.
앱 소유자는 방사선종양학과 전문의이고 원칙은 "모든 표기와 결정은 근거 기반, 근거를 부풀리지도 낮추지도 않는다".
홍보물에 "참고 문헌 전부 원문 대조"라고 적었다.

같은 종류의 오류가 반복해서 나왔다. 오늘(2026-10-14)만 해도:
1. **범위 넘침**: '식물성에스트로겐' 태그 하나에 콩 규칙이 걸려, 석류·아마씨에 "두부·된장은 괜찮다 — 상하이 코호트 9,514명…"이 근거로 붙었다.
2. **제목-대상 불일치**: "이소플라본 농축 보충제는 별개" 규칙이 실제로는 홍삼 하나에만 걸려 있었다.
3. **인용-주장 불일치**: 석류 보충제 판정의 출처로 석류를 다루지 않는 미국암학회 지침이 달려 있었다.
4. **원문 미대조**: 초록만 본 문헌을 넣어 "전부 원문 대조"가 거짓이 될 뻔했다.
과거에도: ESPEN 지침 원문에 '섬유'가 0건인데 섬유 규칙의 출처로 달려 있었음, KDRI 수치가 실제 KDRI 와 다름, 하위군 값을 전체 값처럼 씀, 종설·n=5 를 인용하며 등급 B.

## 네가 할 일
배정된 항목(아래 '배정')을 **하나도 빠짐없이** 검토한다. 항목 자료는 `items.json`(같은 폴더)에 있다 —
필드: id, level, title, reason, evidence, refIds, references(출처 서지·url·주석), match(무엇에 걸리는가), phases, subtypes,
scope.foodCount / scope.foodSample / scope.supplements (그 규칙이 실제로 붙는 음식·영양제 표본), file(소스 위치).
ingredientRule 은 건강기능식품 제품명·기능성 문구에 match 낱말이 보이면 걸리는 원료 규칙이다(byCancer/byMedication/byCondition/duringTreatment 가 조건별 판정).

항목마다 다음 다섯 가지를 확인한다.
A. **인용-주장**: reason 의 각 사실 진술·숫자(HR, %, 명, mg, 기간 등)가 인용한 출처에 실제로 있는가.
   출처 원문(PMC 전문, 학회·기관 공개 PDF/페이지)을 직접 열어 확인한다. 원문을 못 열면 PubMed 초록으로 확인하고 그 사실을 적는다.
   숫자가 하위군 값인지, 1차/2차 종점인지, 위험비인지 절대차인지까지 본다.
B. **범위**: scope(실제로 붙는 음식·영양제)가 근거가 다루는 대상과 같은가. 근거가 다루지 않는 음식에까지 붙으면 오류.
   title 이 특정 음식을 말하는데 다른 음식에 붙어도 오류.
C. **등급**: evidence 등급이 인용한 연구 설계와 맞는가. A=RCT·메타분석, B=대규모 전향 코호트, C=소규모·후향·기전·종설,
   G=주요 학회·기관 지침의 합의(단독 저자 종설은 G 불가). 판정 수준(level)이 근거 강도에 비해 지나치거나 모자라지 않은가.
D. **원문 공개 여부**: 각 출처를 무료 원문으로 볼 수 있는가(PMC / 공개 PDF / 기관 페이지) 아니면 구독제라 초록만인가.
E. **반대 근거**: 핵심 주장에 대해 반대 방향의 근거를 최소 한 번 검색한다(PubMed). 결론을 바꿀 만한 것이 있으면 적는다.

도구: PubMed MCP 도구(search_articles, get_article_metadata, get_full_text_article(pmc_ids 배열), convert_article_ids),
WebFetch(기관·학회 페이지), WebSearch. 소스 코드는 읽기만 하고 **절대 수정하지 마라**(Edit/Write 로 프로젝트 파일을 건드리지 말 것).
결과 파일만 이 폴더에 쓴다.

## 하지 말 것 (규칙·약속)
- NCCN 구독자용 PDF 는 이용약관상 쓰지 않는다(공개 JNCCN 게재판만). Liverpool 약물상호작용 DB 의 API 는 키가 필요하니 우회하지 말고 공개 페이지만.
- 블로그·유튜브·개인 사이트는 근거로 쓰지 않는다.
- 이미 전문의가 정한 판정 수준(예: 자몽은 타목시펜·레트로졸 '피하세요', 아나스트로졸·엑스메스탄·ADT '주의', '금기' 낱말 금지, 덜 익힌 동물성 '피하세요')은 **판정 자체를 바꾸자고 하지 말고**, 이유 문장·출처·숫자의 정확성만 본다. 바꿀 만한 근거가 있으면 "판단 필요"로만 적는다.
- 확인하지 못한 것을 확인했다고 쓰지 않는다. 추정은 추정이라고 적는다.

## 결과 형식 — `findings-<배정이름>.json` 로 이 폴더에 저장
```json
{ "batch": "...", "reviewed": <검토한 항목 수>, "items": [
  { "id": "규칙 id", "verdict": "ok | error | warn | judgement",
    "problems": [ { "type": "claim|number|scope|grade|fulltext|counter|other",
                    "detail": "무엇이 왜 틀렸나 (한국어)",
                    "source_quote": "출처 원문에서 그대로 옮긴 짧은 문장(영문 그대로, 25단어 이하)",
                    "source_loc": "PMID/PMCID/URL + 절·표 위치",
                    "fix": "고친 한국어 문장 또는 출처 교체안(구체적으로)" } ],
    "refs_fulltext": { "<refId>": "fulltext-PMC… | fulltext-url | abstract-only | not-found" } } ] }
```
verdict: ok=문제없음, error=사실·숫자·범위·인용이 틀림(고쳐야 함), warn=부정확·초록만·애매(손볼 만함), judgement=판정 수준을 바꿀지 전문의 판단이 필요.
**모든 배정 항목이 items 에 있어야 한다**(ok 도 포함). 마지막에 한국어로 3~8줄 요약을 최종 답변으로 돌려줘(파일 경로 포함).
